# pursuit

Self-hosted job-application tracker for one person, driven from the command line. Agents prepare applications; a human token with the `approve` scope is what allows a submit. The product is **Hire Pursuit** — the repository, binary and every CLI command stay `pursuit`.

- **CLI-first.** The CLI is the agent interface. There is no MCP server — agents call the CLI, which calls the HTTP API.
- **One pipeline.** Applications move `to_apply` → `preparing` → `awaiting_review` → `approved` → `submitting` → `submitted`, with `needs_input` and `failed` as stops along the way.
- **Approval is a human act.** `pursuit approve` requires an `approve`-scoped token and only enqueues a submit — it never clicks Submit itself.

## Auth model

Bearer token, `Authorization: Bearer $PURSUIT_TOKEN`. Three scopes:

| Scope | Grants |
| --- | --- |
| `read` | List and get. |
| `write` | Includes `read`. Prepare applications, mutate records. |
| `approve` | Includes `read`, not `write`. The only scope that can move work into `submitting`. |

A write token can prepare an application all the way to `awaiting_review`; it cannot push it further without an approval from an `approve`-scoped token.
